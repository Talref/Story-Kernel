# Experiment 0.1a — Interactive Kernel Slice

## Status

Implementation for [GitHub issue #1](https://github.com/Talref/Story-Kernel/issues/1).

This is a local laboratory harness for the first complete interaction path:

`human -> C (Gradio/runtime) -> B (typed capabilities) -> A (SQLite world)`

It tests whether a model can recover and mutate persistent structured state through a narrow
contract after its conversation context has been discarded. It is not a roleplay application,
benchmark suite, or production service.

## Setup

Requirements:

- Python 3.12 or newer;
- [`uv`](https://docs.astral.sh/uv/);
- a NanoGPT API key for live model turns.

Install the locked environment:

```shell
uv sync
```

Copy `.env.example` to `.env` and set the key locally:

```dotenv
NANOGPT_API_KEY=your-key-here
```

`.env` and local SQLite files are ignored by Git. The key is held at the provider edge and is
redacted from persisted conversations, execution records, world data sent to the UI, and exports.

## Unified launcher

Launch the full harness:

```shell
uv run story-kernel run
```

The default database is `.story-kernel/story-kernel.db` and the default interface is
`http://127.0.0.1:7860`. Options are available with:

```shell
uv run story-kernel run --help
```

Persistence can be initialized without launching Gradio:

```shell
uv run story-kernel init
```

## A — persisted world

SQLite contains separate records for:

- worlds and their current monotonic revisions;
- optional immutable/versioned object definitions;
- mutable world-local object instances;
- lifecycle-preserved relations between instances;
- provenance sources;
- idempotent committed transactions and their events;
- B prompt versions;
- conversations and messages;
- execution traces.

Object instances can be created without definitions. This is the normal path in 0.1a and keeps
the required definition/instance distinction without expanding the model-facing authoring surface.

Current object/relation rows answer **what is true now**. Committed transaction and event rows
answer **how it became true**. A mutation changes both atomically. Every mutation advances the
bound world's revision once; affected objects or relations receive that revision.

Mutation calls may carry an `expected_world_revision` and an entity-specific expected revision.
Stale preconditions fail without changing state. Every mutation also has a `command_id`; replaying
the same command and arguments returns its prior result, while reusing the ID for different input
is rejected.

Experiment 0.1a binds a single default world and persistent `world` scope in runtime context. The
model cannot redirect a tool to another world or scope through arguments.

## B — primitive application contract

The runtime exposes only these generated, Pydantic-validated tool schemas:

- `create_object`
- `inspect_object`
- `search_objects`
- `set_attribute`
- `add_relation`
- `list_relations`
- `remove_relation`

`search_objects` is intentionally deterministic: it matches text against IDs, world-defined types,
and structured attributes. It is discovery, and callers should inspect candidate IDs before relying
on them. No embedding or vector system is part of this experiment.

The model runtime receives the capability service and a narrow conversation/ledger protocol. It
does not receive a SQLAlchemy engine, session, repository, reset operation, or arbitrary JSON patch
operation.

The editable application prompt is versioned separately from both world and conversation state.

## Model integration

The `ModelProvider` boundary normalizes model discovery, messages, tool calls, output, and usage.
The initial `NanoGPTAdapter` uses NanoGPT's subscription model endpoint and OpenAI-compatible chat
completion endpoint. Model IDs are fetched at runtime instead of being hardcoded.

A conversation is pinned to the exact provider and selected model at creation. Changing the visible
selector does not migrate an existing conversation; use **New conversation** to start with another
model.

Each turn permits at most eight tool-call rounds. Validation failures are returned as structured tool
errors so the model can repair an invalid request. Provider and round-limit failures are recorded as
credential-safe execution errors.

## C — inspector behavior

The Gradio surface provides:

- chat;
- searchable subscription-model selection and refresh;
- an editable/versioned B prompt;
- human-readable and raw structured world views;
- execution/tool trace inspection;
- **New conversation** and **Reset world** actions;
- versioned JSON import/export controls.

**New conversation** creates an empty transcript and preserves A. **Reset world** clears objects,
relations, provenance, transactions, and events, and returns the world to revision 0. It preserves
the application prompt, conversations, messages, and execution evidence.

Import validates the top-level experiment format and applies all supported modules in one database
transaction. The temporary bundle keeps world, application, safe model configuration,
conversations, and execution trace in distinct sections. It is not a final package format.

## Execution evidence

Every turn records:

- conversation, world, and scope identifiers;
- contract and prompt versions, including the active prompt;
- selected provider and exact model ID;
- user input and initial model input;
- available tool schemas;
- tool calls, validated arguments, results, reads, writes, and failures;
- world revisions before and after;
- committed transaction and event IDs;
- final response, retries, errors, latency, and available token usage.

The trace is telemetry. Neither it nor the conversation transcript is authoritative world state.

## Automated verification

Run:

```shell
uv run pytest
```

The suite uses in-memory or temporary SQLite databases, scripted model adapters, and HTTP mock
transport. It requires no API key or network access. It covers the issue's acceptance criteria plus
scope isolation, optimistic concurrency, command idempotency, atomic relation lifecycle, provider
translation, model pinning, tool repair, and credential redaction.

## Manual smoke test

1. Set `NANOGPT_API_KEY` in `.env` and run `uv run story-kernel run`.
2. Click **Refresh models**, choose a tool-capable subscription model, and click
   **New conversation**.
3. Confirm that the world inspector is empty or reset it.
4. Tell the model two persistent facts that naturally require objects and a relation, for example:
   “Remember that the bronze bell is stored in the north archive.”
5. Inspect both world views and the execution trace. Confirm that committed objects/relations,
   revision changes, transaction IDs, and event IDs are visible.
6. Ask where the bell is stored. Confirm that the trace shows world tools retrieving the answer.
7. Correct the fact, for example: “The bell has moved to the south archive.” Confirm that current
   structured state changes and prior committed events remain inspectable.
8. Click **New conversation**. Confirm that chat is empty while the world remains populated.
9. Ask where the bell is stored again. Confirm that the answer uses tool reads in the new execution
   rather than previous transcript context.
10. Export the experiment, inspect its separate sections, reset the world, import the document, and
    confirm that the supported state round-trips.

## Deliberate limits and next experiment

There is no D/meta-runtime, dynamic skill system, domain ontology, epistemic projection system,
branching, vector retrieval, multi-agent orchestration, or production infrastructure here.

Experiment 0.1b can freeze a canonical fixture and compare monolithic prompt, text RAG, and object
runtime arms. Those evaluation fixtures and matched baselines are intentionally not smuggled into
this implementation issue.
